# SSH access to ephemeral environments

## Personal setup in Console

Open **Integrations → SSH environment → Connect**. Enter the full WSS SSH
tunnel URL, SSH username, a dedicated private key without a passphrase, and the
server's verified public host key. Choose an access period (24 hours, 7 days,
or 30 days), then save. The next screen shows the public key to register with
your environment. Saving does not perform registration or claim a successful
connection test.

Private keys are write-only and encrypted with Console's existing Active Record
encryption settings. Proxy-sync decrypts them only for the paired Iron SSH
companion. The sandbox never receives the upstream private key. **Edit or
renew** changes the target/key or starts a new access period; leaving the key
blank preserves it. **Disconnect** removes the stored private key and revokes
new connections and active leases on their next authorization check.

Each user has one active SSH environment, available through the `ee` tool.
Console sessions match the authenticated Console account. Slack DMs and channel
turns match the owner's verified Slack SSO subject and workspace, never email
or editable principal labels. Link that Slack identity to the Console account
before using the connection from Slack.

Deploy Console's database migration before relying on the new proxy-sync
authorizer. UI-managed connections take precedence over the operator file
below, including when expired or disconnected, so an old file entry does not
silently reactivate access. Operators must still enable the SSH companion and
allow the destination through the deployment's network policy.

## Operator configuration

This opt-in pilot requires an Iron image containing `iron-ssh`. The companion
uses sshpiper's transport library in a separate Go module; ordinary HTTP
proxying keeps its existing crypto dependencies. Build that image locally from
the companion's Dockerfile, then build the Centaur proxy wrapper with
`--build-arg IRON_PROXY_IMAGE=<local-image>`. Do not enable this on the default
published image until the companion is released and pinned by digest.

On api-rs, set a persistent, random `CENTAUR_EE_SSH_SEED` of at least 32 bytes
through the deployment's secret mechanism. Set `KUBERNETES_IRON_PROXY_SSH_ENABLED=true`,
`KUBERNETES_IRON_PROXY_SSH_ROUTE=ee`, and
`KUBERNETES_IRON_PROXY_SSH_WORKSPACE=/workspace` through `apiRs.extraEnv`. api-rs derives different disposable client and
proxy-host keys for each sandbox. Keep the seed stable across api-rs restarts;
changing it requires replacing retained sandboxes and their proxies. The seed
is never sent to sandbox or proxy pods. Proxy repair preserves identities via
the same seed and sandbox ID.

Mount an operator-controlled JSON grants file and private-key files in
proxy-sync only using `proxySync.extraVolumes` and `extraVolumeMounts`. Set `CENTAUR_EE_SSH_GRANTS_FILE` to that JSON file through `proxySync.extraEnv`. Example:

```json
[{
  "principal": "prn_example",
  "route": "ee",
  "generation": "environment-generation-1",
  "destination": "wss://ee-ssh.dev.example.com/events/events",
  "username": "dev",
  "host_key": "ssh-ed25519 <verified-upstream-public-host-key>",
  "private_key_file": "/run/ee-keys/user-example",
  "expires_at": "2026-12-01T00:00:00Z"
}]
```

Register the matching dedicated public key in the EE application. Confirm the
upstream SSH host key through a trusted channel; there is no trust-on-first-use
or disabled TLS validation. The destination path is the full wstunnel v11
upgrade path: `/<configured-prefix>/events`, commonly `/events/events`.
Only WSS on port 443 is allowed by this pilot's authorization endpoint. The
Iron companion also supports explicitly configured direct TCP SSH in standalone
mode. Neither path needs Kubernetes exec or a Kubernetes service-account token.

The authorizer authenticates the proxy's existing private bearer token. Personal
`user`, `console_user`, and `slack_dm` sessions use their own grant. A
`slack_channel` session uses only the Slack user's principal bound by the control
plane for the current turn, derived from the verified ingress event. The thread
author and channel grants do not confer SSH access. Missing requester identity,
non-Slack requesters, and workflows are denied; the tool cannot supply a
requester or select another user's key. Each authorization and lease renewal
rereads the binding. Changing or clearing it revokes the previous user's lease,
and the binding generation prevents a lease surviving a switch away and back.
The same personal grant works in a DM and in that user's channel turns; no
channel grant is needed. Downstream key verification happens in the paired proxy
against the key api-rs supplied. A sandbox supplies only a route alias, never an
upstream host or a credential reference.

Grants are reread on every authorization and renewed at five-second intervals
with a maximum 30-second lease. Removing a grant, changing its key/destination,
unassigning its proxy, or losing the authorizer closes the connection on the
next check or lease expiry. Update files atomically. Rotation requires updating
the matching public key in the EE as well as the private-key file. Removing a
local grant does not remove an EE public key.

Supported operations are non-PTY exec and SFTP. Forwarding, agent forwarding,
PTY, shell, environment injection, X11, and other subsystems are rejected.
Connection audit metadata excludes credentials and command output. SSH access
permits agent code to use the EE's own credentials and network permissions;
review that boundary before granting access. Iron's local HTTP egress policy
does not extend to programs running in the EE.

To disable, remove the grants, allow active connections to close, then disable
the SSH feature and replace affected sandbox/proxy pods. Workspace changes in
the EE remain intact.
